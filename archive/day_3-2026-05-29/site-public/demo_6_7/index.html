Tree shaking, made physical — same logic, 35× size difference

Full import (no tree shaking benefit)
import _ from 'lodash';

_.map([1, 2, 3], x => x * 2);
~70 KB shipped
Named import (only what you use)
import map from 'lodash/map';

map([1, 2, 3], x => x * 2);
~2 KB
Same behaviour. One line of difference. The bundler walks the import graph from your entry point; if you never reference _.shuffle, _.debounce, or the other 297 lodash functions, it drops them. That's tree shaking. It works because ES modules are statically analyzable — the bundler can prove what you do and don't use.

Code splitting in plain React — React.lazy(), five lines

const Heavy = React.lazy(() => import('./Heavy'));

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Heavy />
    </Suspense>
  );
}
React.lazy is React's only bundler-aware API. The dynamic import() tells your bundler "this module is a separate chunk; fetch it later." The bundler does the actual splitting. React provides the runtime primitive (Suspense) to render a fallback while it loads. Same code works with Vite, webpack, or Next.
